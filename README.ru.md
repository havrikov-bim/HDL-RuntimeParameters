# HDL Runtime Parameters

**Статус: в разработке. Основные функции реализованы; продолжаются тестирование и доработка.**

[English](README.md) · Русский

Автоматическое вычисление и обновление общих параметров экземпляров семейств в Revit. Реализовано на Python через pyRevit и Revit IUpdater.

Автор: Dmytro Havrikov. Версия: 1.0.

## Идея

Общий параметр хранит значение, которое можно использовать в марках, спецификациях и фильтрах. Но для некоторых параметров это значение нужно вычислять и поддерживать актуальным при изменении элемента.

Для этого разработан отдельный механизм: в JSON задаются параметры и область обработки, а в Python-сервисах — правила вычисления значений. При добавлении элемента или изменении его геометрии IUpdater вызывает соответствующий сервис и записывает результат в общий параметр.

Таким образом, с общими параметрами можно работать подобно системным: значение определяется по данным элемента и обновляется автоматически. При этом параметр остаётся общим параметром Revit.

Механизм не ограничен отверстиями. Отверстия используются как практический пример; для других семейств и задач можно подключать свои сервисы.

## Что входит в комплект

| Компонент | Назначение |
| --- | --- |
| Runtime Parameter Updater | Вызывает сервисы при добавлении элементов и изменении их геометрии |
| `absolute_elevation.py` | Вычисляет абсолютную отметку элемента по отметке уровня и смещению от него |
| `op_opening_size.py` | Формирует текстовое представление размера круглого или прямоугольного отверстия |
| Recalculate Parameters | Принудительно пересчитывает значения по тем же правилам и сервисам |

Runtime и команда принудительного пересчёта устанавливаются как два отдельных расширения pyRevit. Они используют одну конфигурацию и одни сервисы.

## Как работает обновление

1. В `config/parameters.json` указываются сервис, общие параметры по GUID и семейства либо категории для обработки.
2. При добавлении элемента или изменении его геометрии IUpdater проверяет соответствие правилам.
3. Сервис вычисляет значения и возвращает их механизму обновления.
4. Изменившиеся значения записываются в параметры в рамках той же транзакции Revit.

Отдельная транзакция для runtime не создаётся. DocumentChanged и Idling не используются. Если значение осталось прежним, повторная запись не выполняется.

## Абсолютная отметка

Сервис `absolute_elevation.py` рассчитывает `SP_BOM_Absolute_Elevation`:

```text
Отметка элемента = Level.Elevation + INSTANCE_ELEVATION_PARAM
```

Используются отметка связанного уровня и смещение экземпляра от уровня. Результат записывается во внутренних единицах Revit.

Формула не содержит отдельного преобразования в координаты Survey Point или общую систему координат. Её соответствие принятой системе отметок нужно проверить в конкретном проекте.

## Размер отверстия

Сервис `op_opening_size.py` формирует значение текстового общего параметра `SP_OP_Size` в зависимости от формы отверстия.

| Форма | Исходные параметры | Представление |
| --- | --- | --- |
| Прямоугольная | `SP_OP_Width`, `SP_OP_Height`, `SP_OP_Description` | Описание на первой строке; ширина × высота с обозначением `(H)` на второй. Размеры в сантиметрах |
| Круглая | `SP_OP_Diameter`, `SP_OP_Description` | Диаметр с символом `ø`, обозначением дюймов и описанием |

Например, отверстие 400 × 250 мм с описанием `Opening`:

```text
Opening
40 x 25(H)
```

Круглое отверстие диаметром 4 дюйма:

```text
ø4" Opening
```

Числа выводятся с точностью до двух знаков после запятой, без лишних нулей. Исходные параметры сначала ищутся у экземпляра; если параметра нет — у типа.

В текущем сервисе заданы четыре семейства: `BL Opening Rect Wall`, `BL Opening Rect Floor`, `BL Opening Round Wall`, `BL Opening Round Floor`. Для других имён или форм сечения потребуется дополнить сервис.

GUID выходного параметра: `51c5bd0e-4839-43aa-80f8-ffe67faa1a7e`. Он указан и в JSON, и в константе `TARGET_GUID` сервиса. При использовании другого общего параметра нужно изменить оба значения.

## Принудительный пересчёт

Изменение исходных данных не всегда вызывает IUpdater для самих экземпляров. Например, после изменения данных уровня или базовой точки проекта требуется повторно вычислить отметки существующих элементов. Аналогично может потребоваться обновление текста после изменения описания.

Для таких случаев предусмотрена команда:

**HDL → Parameters → Recalculate Parameters**

Она обрабатывает все подходящие элементы текущего проекта по действующим правилам. Выбор элементов, активный вид и Scope Box не ограничивают обработку. Связанные модели не изменяются.

Пересчёт выполняется одной транзакцией. По завершении выводятся количество проверенных и обновлённых элементов, обновлённых параметров и ошибок.

Принудительный пересчёт повторно выполняет существующие формулы. Если формула возвращает прежнее значение, параметр не изменится. Сама команда не меняет систему координат или правила определения отметки.

Подробности: [Recalculate Parameters](docs/RECALCULATE.md).

## Установка

1. [Скачать полный комплект](https://github.com/havrikov-bim/HDL-RuntimeParameters/raw/refs/heads/main/downloads/HDL_RuntimeParameters_v1.0_complete.zip).
2. Скопировать папки `HDL_RuntimeParameterUpdater_IUpdater_Clean_v1.0.extension` и `HDL_Recalculate_Parameters.extension` в каталог расширений pyRevit, обычно `%APPDATA%\pyRevit\Extensions`.
3. Обе папки должны находиться рядом. Команда пересчёта находит runtime в соседних папках расширений.
4. Удалить предыдущую версию runtime из каталога расширений. Не оставлять одновременно несколько активных копий и не смешивать эту версию с прежней реализацией на DocumentChanged/Idling.
5. Настроить `config/parameters.json`: указать фактический GUID параметра абсолютной отметки и имена нужных семейств. Для размера отверстия уже указаны четыре семейства и GUID `SP_OP_Size`.
6. Убедиться, что необходимые общие параметры экземпляров существуют и доступны для записи через API. Расширение не создаёт параметры и их привязки.
7. Перезагрузить pyRevit. Проверить работу на нескольких элементах, затем выполнить принудительный пересчёт существующих экземпляров при необходимости.

Требуются Autodesk Revit и pyRevit. Для загрузки Python-сервисов используется `imp`, для получения идентификаторов категорий — `ElementId.IntegerValue`. Совместимость с конкретными версиями Revit и Python-движками pyRevit пока не проверена систематически.

## Настройка и ограничения

Имена семейств и категорий сравниваются точно. Если в правиле указаны и семейства, и категории, достаточно совпадения с любым из этих списков. Категория расширяет область обработки, а не ограничивает список семейств. Имена категорий зависят от языка Revit.

При открытии проекта все существующие элементы автоматически не пересчитываются. Обновление runtime связано с добавлением элемента или изменением его геометрии. Изменения других параметров, уровней и проектных данных не имеют отдельного механизма распространения зависимостей. В этих случаях используется принудительный пересчёт.

В текущей версии нет редактора формул, графа зависимостей и защиты вычисляемых значений от ручного редактирования. Runtime пропускает многие ошибки без подробного отчёта. Команда пересчёта считает ошибки по элементам, но не выводит их подробный список; часть изменений элемента могла быть выполнена до ошибки.

## Проверка и документация

Для сервиса размера отверстия выполнены девять локальных проверок: форматирование, единицы, чтение параметров типа, отсутствующие данные и GUID результата. Это проверки вычислений с подстановками Revit API, а не выполнение внутри Revit.

```bash
python -m unittest discover -s tests -v
```

Регистрацию IUpdater, события обновления, запись параметров и Undo/Redo нужно проверить в рабочем окружении Revit.
